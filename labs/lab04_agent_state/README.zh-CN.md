# Lab 04 — Agent 状态、检查点与恢复

[English](README.md) · [简体中文](README.zh-CN.md)

在写入提交之后、检查点更新之前制造崩溃，再恢复有界工具循环。脚本规划器提供固定计划，便于复现故障；它不是自主决策的 LLM Agent。

## 运行

在仓库根目录，完成依赖安装后运行（Python 3.11+，推荐 3.12）：

```bash
python -m labs.lab04_agent_state.app
python -m pytest tests/test_agent_state.py -q
```

无需 API Key 或网络。演示使用临时目录并在结束后清理，不修改你的项目文件。

## 跟着做

1. 先读 `agent.py`：状态存储计划、下一调用位置、已消耗尝试次数、结果和状态。
2. 运行演示：暂停在 `waiting_approval`；可信控制器审批后，工具完成写入，再模拟崩溃。
3. 重新创建注册表和 Agent，只从数据库恢复，不保留内存审批。重试读取已提交回执，最终 `completed`、尝试次数 3、Issue 数量 1。
4. 读子进程测试：由另一个 Python 进程恢复任务；再看取消、操作冲突和预算持久化测试。

## 练习

1. 将 `max_steps=1`：第一次被拦截也消耗尝试预算，再恢复则 `budget_exhausted`；等待不会重置预算。
2. 执行前取消任务，验证不会创建 Issue；重复运行已完成任务，结果不变。
3. 理解状态机后再把脚本计划替换为模型提议，校验、审批和持久化回执仍放在规划器之外。

## 边界与局限

每个任务只允许一个 Worker；未实现分布式锁或并发取消协议。当前只实现尝试次数预算，没有时间/Token 预算。未预料的存储错误会抛出，重试前需检查持久状态。取消在 run 调用之间生效，不能撤销已经提交的写入。检查点是可信本地状态，不是沙箱；外部 API 仍需要结果核对。
