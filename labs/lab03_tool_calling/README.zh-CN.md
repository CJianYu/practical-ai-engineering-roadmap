# Lab 03 — 工具调用、审批与幂等

[English](README.md) · [简体中文](README.zh-CN.md)

校验工具调用，拦截未审批写入，再重复执行已审批操作而不产生重复记录。Issue 只存在本地 SQLite 中，不会发送到 GitHub。

## 运行

在仓库根目录，完成依赖安装后运行（Python 3.11+，推荐 3.12）：

```bash
python -m labs.lab03_tool_calling.app
python -m pytest tests/test_tool_calling.py -q
```

无需 API Key 或网络。演示使用临时目录并在结束后清理，不修改你的项目文件。

## 跟着做

1. 先读 `tools.py`：注册表只暴露 `search_docs` 和 `create_issue`，Schema 拒绝未知工具/字段与错误类型。搜索返回固定政策样例，并非真实搜索引擎。
2. 运行演示：首次写入被拦截，可信演示控制器随后明确批准该操作；之后两次调用返回同一个 Issue ID，`issue_count` 为 1。
3. 查看 `fingerprint`：审批覆盖工具、完整参数和操作 ID。模型不能塞入 `approved` 字段，也不能调用 `approve` 工具。
4. 查看事务：本地 Issue 与回执一起提交；同一操作 ID 改参数后会失败，即使新参数另获审批。

## 练习

1. 批准后改正文，观察拒绝结果；真正的新操作需要新 ID 和新审批。
2. 运行事务回滚测试：回执写入失败时，Issue 写入也回滚。
3. 用 Lab 02 替换固定检索；权限判断仍留在模型外的调度层。

## 边界与局限

这是单用户模拟器，不是生产授权系统；进程和数据库必须可信。未执行的审批在重启后失效，已提交回执可以直接重读，因为没有新写入。本地事务不能让远端 GitHub/API 调用原子化：需要服务端幂等或先核对不确定结果再重试。尚未实现租户隔离、审批计时过期或凭据管理。
