# Maintainer Playbook

This project will earn trust through useful releases, not a one-time README launch.

## Positioning

Keep the promise narrow:

> A practical, eval-driven roadmap for software engineers becoming Applied AI Engineers.

Avoid becoming a generic “everything about AI” list. New material must support the core learner and the Learn → Build → Prove → Explain loop.

## Release cadence

A sustainable initial cadence:

- **v0.1** — full roadmap, templates, two labs;
- **v0.2** — tool calling and workflow lab;
- **v0.3** — agent harness and checkpointing lab;
- **v0.4** — evaluation harness and error-analysis examples;
- **v0.5** — safety and prompt-injection lab;
- **v0.6** — tracing, budgets, and production report.

Publish one meaningful release every one or two weeks. Each release should have a runnable artifact, a screenshot or result table, and a concise changelog.

## Content loop

For each release, create one standalone post:

1. the engineering problem;
2. the baseline;
3. the experiment;
4. the measured result;
5. the code and learning module.

“Here is what changed and what the eval showed” is more valuable than “please star my repository.”

## Community flywheel

- Label small, concrete `good first issue` tasks.
- Invite learners to submit anonymized eval cases and weekly reports.
- Feature high-quality community projects in a showcase.
- Review resource additions strictly to prevent link-list inflation.
- Close stale or marketing-only submissions politely and quickly.

## Repository metadata

Suggested description:

> An eval-driven, project-based roadmap for software engineers becoming Applied AI Engineers.

Suggested topics:

```text
ai-engineering, applied-ai, llm, rag, ai-agents, evals,
llmops, roadmap, generative-ai, learning-path
```

## Launch checklist

- [ ] README explains audience, duration, and outcome in the first screen
- [ ] English and Chinese versions are aligned
- [ ] At least two labs run locally
- [ ] CI is green
- [ ] Issues and PR templates exist
- [ ] License, contributing guide, code of conduct, and security policy exist
- [ ] One public progress post is ready
- [ ] The next release has a clear scope

## Metrics worth tracking

- stars and unique visitors, but not in isolation;
- README-to-lab click-through;
- clones and forks;
- repeat contributors;
- completed learner projects;
- issue quality and time to first response;
- release cadence.

The strongest long-term metric is how many people can show a real evaluated system because of the roadmap.
